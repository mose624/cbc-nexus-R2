Chapter orientation

Purpose, scope and prerequisites

Computer science is the systematic study of computation and computational systems. It investigates how problems can be represented, which problems can be solved by algorithms, how algorithms can be implemented efficiently, and how people and organisations can use computing systems responsibly. Programming is an important part of the discipline, but computer science is broader than learning a programming language or operating a computer.

This chapter establishes a vocabulary for later study of programming, algorithms, computer architecture, databases, operating systems, networking, artificial intelligence and cybersecurity. It assumes basic secondary-school mathematics and ordinary familiarity with using a digital device. No previous programming experience is required.

Curriculum alignment: The chapter is mapped to introductory foundations in the ACM/IEEE-CS/AAAI Computer Science Curricula 2023 (CS2023), particularly Systems Fundamentals, Architecture and Organization, Software Development Fundamentals, Mathematical and Statistical Foundations, and Society, Ethics, and the Profession. CS2023 is a curricular reference—not an accreditation certificate for this learning resource. Individual universities may prescribe additional outcomes and local requirements.

Learning outcomes

After studying and completing the practical work, a learner should be able to:

1. Distinguish computer science from computer literacy and information technology.
2. Apply decomposition, pattern recognition, abstraction and algorithm design to a problem.
3. Distinguish data, information and knowledge, and assess basic data quality.
4. Convert between decimal, binary and hexadecimal representations.
5. Explain the roles of the CPU, memory, storage, input/output and buses.
6. Trace a simplified fetch–decode–execute instruction cycle.
7. Explain the operating system's role and the memory hierarchy.
8. Describe packet-based networking and the purpose of common protocols.
9. Identify ethical, privacy, accessibility and security responsibilities.
10. Test a small computational model and communicate evidence-based conclusions.

1.1 The discipline of computer science

Computer science examines computation as a process that transforms representations of information according to precisely defined rules. A computational problem specifies what is given (the input), what result is required (the output), and the conditions a correct solution must satisfy. An algorithm is a finite, sufficiently precise sequence of steps for solving a class of such problems.

For example, a university may need to identify students whose weighted mean mark is at least 50%. The problem is not simply “use a spreadsheet.” It requires a definition of the input marks, their weights, the treatment of missing or invalid values, the formula, the threshold, and the output format. A computer scientist analyses these requirements before choosing a programming language or application.

These fields overlap. A secure online learning platform, for example, involves algorithms and databases (computer science), reliable development practices (software engineering), servers and networks (IT), and the needs of learners and administrators (information systems).

Core questions asked by computer scientists

  • Correctness: Does the system produce the required result for every valid input?
  • Efficiency: How do processing time and memory use grow as the input becomes larger?
  • Feasibility: Can the problem be solved within available computational resources?
  • Reliability: How does the system behave when components fail or inputs are unexpected?
  • Security and privacy: Can data or services be accessed or altered by unauthorised parties?
  • Human impact: Is the system accessible, fair, understandable and appropriate for its users?

1.2 Computational thinking and problem formulation

Computational thinking is a method of analysing and expressing problems so that solutions can be carried out systematically. It is useful in programming, science, business, education, logistics and public services. Four commonly taught practices are decomposition, pattern recognition, abstraction and algorithm design. Evaluation is applied throughout.

A. Decomposition

Decomposition breaks a large problem into smaller parts that can be understood, developed and tested separately. For a student-results system, parts might include data entry, validation, weighted-mark calculation, grade assignment, report generation and secure storage. Each part can have its own specification and tests.

B. Pattern recognition

Pattern recognition identifies similarities across examples. If every course unit uses the same weighted-mark rule, a single calculation procedure can be reused. Reuse reduces duplicated logic, but the programmer must verify that the cases genuinely share the same rule.

C. Abstraction

Abstraction keeps details relevant to the current task and hides details that are not. A student record may be modelled as a student number, name, programme and registered units. The colour of the student's shoes is irrelevant to calculating a course average. Abstraction is not careless omission: it requires a reasoned decision about which details affect the result.

D. Algorithm design

An algorithm specifies the steps that transform inputs into outputs. A good algorithm is unambiguous, finite, sufficiently precise and correct for the stated problem. It should also account for exceptional cases.

Worked example 1 — Weighted course mark

A course uses coursework worth 40% and a final examination worth 60%. A learner scores 72/100 in coursework and 65/100 in the examination. Calculate the final percentage.

Step 1: Define inputs. Coursework C = 72; examination E = 65; weights are 0.40 and 0.60.

Step 2: State the model. Final mark M = (0.40 × C) + (0.60 × E).

Step 3: Substitute. M = (0.40 × 72) + (0.60 × 65) = 28.8 + 39.0 = 67.8%.

Step 4: Check. The weights sum to 1.00 and the result lies between 0 and 100, as expected for valid component marks.

Step 5: Consider edge cases. What happens if an examination mark is missing? What if a mark is −4 or 108? A responsible system validates the inputs and follows the institution's approved missing-mark policy rather than silently treating missing data as zero.

Writing an algorithm in pseudocode

Pseudocode describes the logic without requiring a particular programming language. It should be consistent, readable and precise.

INPUT coursework, examination
IF coursework < 0 OR coursework > 100 THEN
    OUTPUT "Invalid coursework mark"
ELSE IF examination < 0 OR examination > 100 THEN
    OUTPUT "Invalid examination mark"
ELSE
    final_mark = 0.40 * coursework + 0.60 * examination
    OUTPUT final_mark
END IF

This example validates range but not missing values or the exact institutional grading policy. A complete specification must define those rules.

1.3 Data, information and knowledge

Data are recorded symbols, measurements or observations. Information is data processed or organised so that it has meaning in a particular context. Knowledge is an interpreted understanding that supports explanation, judgement or action. These terms are related but not interchangeable.

Example — A temperature reading

The number 38.5 alone is ambiguous. It might be a temperature in degrees Celsius, a body temperature, a room reading or a measurement from a machine. When recorded as “38.5 °C, measured at 10:00 using a calibrated clinical thermometer,” it becomes contextualised information. A trained clinician may interpret it with symptoms, age and other evidence to decide what action is appropriate. The number alone does not establish a diagnosis.

Data quality dimensions

Data quality must be designed into collection, storage and processing. Validation can detect some invalid values, but it cannot guarantee that a plausible value is true. A mark of 68 may pass a range check while still belonging to the wrong student.

1.4 How digital computers represent information

Digital computers operate using physical states that circuits interpret as discrete values. Binary uses two symbols, 0 and 1, called bits. A group of eight bits is a byte. Binary is practical because electronic circuits can distinguish ranges of voltage or other physical states more reliably than they can represent an unlimited set of exact values.

Place value in positional number systems

In a base-b number system, each digit is multiplied by a power of b. Decimal is base 10; binary is base 2; hexadecimal is base 16. Hexadecimal uses 0–9 and A–F, where A represents 10 and F represents 15.

Worked example 2 — Convert decimal 45 to binary

Repeatedly divide the decimal number by 2 and record each remainder:

DivisionQuotientRemainder
45 ÷ 2221
22 ÷ 2110
11 ÷ 251
5 ÷ 221
2 ÷ 210
1 ÷ 201

Read the remainders from bottom to top: 45₁₀ = 101101₂.

Verification: 1×32 + 0×16 + 1×8 + 1×4 + 0×2 + 1×1 = 32 + 8 + 4 + 1 = 45.

Worked example 3 — Convert binary 110101₂ to decimal

Write the powers of two from right to left: 2⁰, 2¹, 2², 2³, 2⁴, 2⁵.

110101₂ = (1×32) + (1×16) + (0×8) + (1×4) + (0×2) + (1×1) = 53₁₀.

Worked example 4 — Convert binary to hexadecimal

Group 110101₂ into four-bit groups from the right: 0011 0101. The group 0011 is hexadecimal 3; 0101 is hexadecimal 5. Therefore 110101₂ = 35₁₆. Check: 3×16 + 5 = 53.

Binary arithmetic

Binary addition follows the same positional principle as decimal addition, but each column has only two digits. The key rules are 0+0=0, 0+1=1, 1+0=1 and 1+1=10₂ (write 0 and carry 1).

1011₂ (11₁₀)
+ 0110₂ ( 6₁₀)
--------
10001₂ (17₁₀)

Binary subtraction, signed integers and overflow are studied more fully in computer architecture. In fixed-width arithmetic, a result may exceed the representable range; overflow must be detected or prevented where correctness matters.

Representing text, images and sound

  • Text: character encoding assigns numeric code points or byte sequences to characters. Unicode supports characters from many writing systems; UTF-8 is a widely used variable-length encoding.
  • Images: a raster image is a grid of pixels. Each pixel stores colour information. Resolution and colour depth affect storage requirements.
  • Audio: digital audio samples a continuous signal at regular intervals and quantises the amplitude. Sample rate and bit depth influence quality and file size.
  • Video: video commonly stores a sequence of frames with timing information, often alongside compressed audio.
Worked example 5 — Uncompressed image storage

An image is 800 pixels wide and 600 pixels high, with 24 bits per pixel (8 bits each for red, green and blue). Ignoring headers and compression:

Pixels = 800 × 600 = 480,000.

Storage in bits = 480,000 × 24 = 11,520,000 bits.

Storage in bytes = 11,520,000 ÷ 8 = 1,440,000 bytes, approximately 1.44 MB using decimal units.

Actual file size can be smaller or larger depending on compression, metadata and file format. Distinguish decimal MB (1,000,000 bytes) from MiB (1,048,576 bytes).

1.5 Main components of a computer system

A computer system combines hardware, software, data, procedures, people and communication links. A useful high-level model is input, processing, storage and output. These functions may occur repeatedly and concurrently; a networked system may receive input from remote users and store results on remote servers.

Central processing unit (CPU)

The CPU executes machine instructions. A simplified description identifies the control unit, arithmetic logic unit (ALU) and registers. The control unit coordinates instruction execution. The ALU performs arithmetic and logical operations. Registers are small, fast storage locations inside the processor. Modern CPUs also contain caches, pipelines, multiple cores and specialised execution units.

Main memory and secondary storage

Random access memory (RAM) stores instructions and data currently in use. It is generally volatile: its contents are lost when power is removed. Secondary storage, such as a solid-state drive or hard disk, retains information without power. Storage is generally larger but slower than CPU registers and cache. Removable media and network storage introduce additional considerations such as portability, access control and availability.

Input/output and buses

Input devices convert actions or signals into data; output devices communicate results. Sensors measure physical conditions, while actuators produce physical effects. Communication between components uses interconnection structures such as buses and point-to-point links. A device driver and controller help the operating system coordinate peripheral hardware.

1.6 The stored-program model and instruction cycle

In a stored-program computer, program instructions are held in memory and executed by a processor. A simplified instruction cycle consists of fetching an instruction, decoding it, obtaining required operands, executing the operation and storing or writing back the result. Real processors overlap stages and use advanced mechanisms, but the simplified cycle is essential for understanding the role of the CPU.

Worked example 6 — Trace a simple instruction sequence

Assume a teaching machine has registers R1 and R2 and supports these instructions:

LOAD R1, 7
LOAD R2, 5
ADD  R1, R2
STORE R1, RESULT
InstructionActionR1 after instructionR2 after instruction
LOAD R1, 7Place 7 in R1.7—
LOAD R2, 5Place 5 in R2.75
ADD R1, R2Add R2 to R1 and keep the result in R1.125
STORE R1, RESULTCopy R1 to memory location RESULT.125

The final stored value is 12. This is illustrative pseudomachine assembly, not a claim that every processor uses these exact instruction names or operand rules.

1.7 Memory hierarchy and performance

Computer systems use a hierarchy of storage technologies. The closer a storage level is to the CPU, the faster and more expensive per byte it tends to be, and the smaller its capacity tends to be. The hierarchy exists because a single technology cannot simultaneously provide very high speed, very large capacity and very low cost.

Cache memory stores copies of recently or frequently used instructions and data so the CPU can access them more quickly than main memory. It exploits temporal locality (recently used items may be used again) and spatial locality (nearby memory locations may be accessed soon). A cache hit is served from cache; a cache miss requires fetching data from a lower level.

Virtual memory gives each process an address-space abstraction. The operating system and memory-management hardware map virtual addresses to physical memory. Pages not currently resident may need to be fetched from storage, which is much slower than RAM. Excessive paging can severely degrade performance.

Performance is multidimensional

  • Latency: time taken to complete one operation.
  • Throughput: amount of work completed per unit time.
  • Clock frequency: processor cycles per second; it is not by itself a reliable measure of overall performance.
  • Memory capacity and bandwidth: how much data can be held and how quickly it can be transferred.
  • Energy efficiency: useful work performed relative to power consumed.
Worked example 7 — Data transfer time

A file of 120 megabytes (MB, decimal units) is transferred over a link with a sustained rate of 20 megabits per second (Mb/s). Ignore protocol overhead and rate variation.

Convert megabytes to megabits: 120 MB × 8 = 960 megabits.

Time = data size ÷ rate = 960 Mb ÷ 20 Mb/s = 48 seconds.

In practice, transfer time may be longer because of protocol overhead, congestion, retransmissions, server speed and the difference between advertised and sustained rates.

1.8 Software, operating systems and application programs

Software is a set of instructions and associated data that directs a computer system. System software manages hardware and provides services to applications. It includes operating systems, device drivers, utilities, language runtimes and firmware. Application software helps users perform tasks such as writing documents, analysing data, communicating, learning or managing finances.

An operating system (OS) manages processes, memory, files, input/output devices, users and protection. It provides abstractions so applications do not need to control every hardware detail. The kernel is the privileged core of an operating system. Applications request services through defined interfaces, including system calls.

Processes and files

A program is a passive set of instructions stored as a file; a process is an executing instance of a program with its own execution state and allocated resources. A file system organises persistent data into named files and directories. Permissions and ownership rules help control who can read, modify or execute resources.

Why abstraction matters

A word processor asks the operating system to open a file, allocate memory, display content and communicate with storage. It does not need to know the electrical signalling details of the SSD or the physical timing of the display. The OS and device drivers provide stable abstractions, although applications still need to handle errors such as insufficient storage or denied permissions.

1.9 Networks and the internet

A computer network connects devices so they can exchange data and share services. A local area network (LAN) covers a limited area such as an office or campus. A wide area network (WAN) spans larger geographic areas. The internet is a global network of interconnected networks that communicate using common protocol suites.

Data are commonly divided into packets. Each packet carries addressing and control information so network devices can forward it. Internet Protocol (IP) provides addressing and routing. Transport protocols such as Transmission Control Protocol (TCP) and User Datagram Protocol (UDP) offer different communication properties. The Domain Name System (DNS) translates human-readable domain names into information used to locate network services. HTTP and HTTPS are used for web communication; HTTPS protects the connection using TLS.

Basic network concepts

  • Addressing: identifies network interfaces or services.
  • Routing: selects a path through interconnected networks.
  • Bandwidth: a measure of link capacity; actual throughput is affected by other factors.
  • Protocol: agreed rules for message format, sequencing and handling.
  • Encryption: protects confidentiality of data in transit when correctly configured.

1.10 Computing ethics, privacy, safety and professional conduct

Computing systems affect education, health, finance, employment, public administration and personal relationships. A system can be technically correct yet harmful if it exposes private information, excludes users with disabilities, amplifies bias, produces unsafe decisions or hides how data are used. Ethical analysis is therefore part of system design and evaluation, not an optional final paragraph.

Core professional responsibilities

  • Privacy and confidentiality: collect only necessary personal data, explain its use, restrict access and protect it throughout its lifecycle.
  • Security: use strong authentication, least-privilege access, timely updates, secure backups and responsible vulnerability disclosure.
  • Fairness: examine whether datasets, rules or models disadvantage groups and provide ways to challenge consequential errors.
  • Accessibility: design interfaces that work for people with different abilities, devices, languages and connectivity conditions.
  • Transparency: document assumptions, limitations, data sources and known failure modes.
  • Intellectual property: respect copyright, software licences, attribution and permitted use of data.
  • Environmental responsibility: consider energy use, device lifespan, e-waste and efficient computation.
Laboratory safety and authorisation: Use only devices, networks, accounts and datasets you own or have explicit permission to use. Do not scan, probe, access or disrupt public systems as a class exercise. Use a local virtual machine, sandbox or instructor-provided environment for security demonstrations. Remove or anonymise personal data before sharing student work.

Case study — A student attendance application

A college plans to introduce an attendance application using student photographs and location data. A responsible design review should ask: Is location tracking necessary, or would a less intrusive method work? Who can view attendance records? How long are records retained? How can a student correct a mistaken absence? What happens when a student has no smartphone or connectivity? Could facial recognition perform differently across demographic groups? Is there a human appeal process? The best technical design is not automatically the most ethical design.

1.11 Practical laboratory exercises

These exercises are designed to move from explanation to demonstrated competence. Record your method, results, test evidence and interpretation in a laboratory notebook. Use a local computer or authorised learning environment.

Lab A — Number-system conversion

  1. Convert decimal values 19, 45, 127 and 200 into binary using repeated division by two.
  2. Convert binary values 10101₂, 111000₂ and 10011010₂ into decimal using place values.
  3. Convert 11101111₂ into hexadecimal by grouping four bits from the right.
  4. Verify every answer by converting it back to the starting base.
  5. Explain why leading zeros may be added when representing a fixed-width value.

Lab B — Build a simple data-validation program

Using Python 3 or another approved language, write a program that asks for two assessment marks, rejects values outside 0–100, calculates a weighted mark using 40% and 60%, and displays the result to one decimal place. Test ordinary, boundary and invalid inputs.

coursework = float(input("Coursework mark (0-100): "))
exam = float(input("Examination mark (0-100): "))

if not (0 <= coursework <= 100):
    print("Invalid coursework mark")
elif not (0 <= exam <= 100):
    print("Invalid examination mark")
else:
    final_mark = 0.40 * coursework + 0.60 * exam
    print(f"Final mark: {final_mark:.1f}%")

Test plan: Try 72 and 65 (expected 67.8); try 0 and 100 (expected 60.0); try 100 and 100 (expected 100.0); try −1 and 70 (must reject); try 75 and 101 (must reject). Also test non-numeric input and improve the program to handle conversion errors. This first version intentionally does not implement an institution's full grading or missing-mark policy.

Lab C — Observe system resources

  1. Open the system task/process monitor on your own computer.
  2. Identify CPU utilisation, memory use, running processes and storage capacity.
  3. Open a permitted application and observe how resource use changes.
  4. Close the application normally and observe whether its process terminates.
  5. Explain why one snapshot cannot establish the overall performance of a computer.

Lab D — Design a small information system

Design a library-loan system on paper. Identify users, data items, operations, inputs, outputs, access restrictions and likely errors. Draw a context diagram and describe what happens when a book is borrowed, returned or reported lost. Include privacy and backup requirements.

Laboratory report structure

  1. Title, date, objective and learning outcome.
  2. Equipment/software and version information.
  3. Method, assumptions and input data (use synthetic data).
  4. Results, tables, screenshots or code excerpts where appropriate.
  5. Test cases: expected result versus actual result.
  6. Discussion of errors, limitations, security and improvements.
  7. Conclusion and references.

1.12 Chapter summary and key terms

  • Computer science studies computation, algorithms, information and computational systems.
  • Computational thinking uses decomposition, pattern recognition, abstraction and algorithm design.
  • Data become information when interpreted in context; information supports knowledge and action.
  • Digital systems encode information using binary states. Bits, bytes and positional number systems are foundational.
  • The CPU executes instructions and coordinates operations with memory and input/output devices.
  • Memory hierarchy balances speed, capacity and cost; caches exploit locality.
  • The operating system manages resources and provides services to applications.
  • Networks use protocols and packet forwarding to exchange information across connected devices.
  • Professional computing requires privacy, security, fairness, accessibility, transparency and responsible practice.

1.13 Examination and revision questions

Attempt the questions before opening the guidance. For calculation questions, show each conversion and intermediate step. For discussion questions, use examples and explain trade-offs rather than listing terms only.

  1. Define computer science and explain two ways in which it differs from computer literacy.
    Answer guidance

    Computer science systematically studies computation, algorithms, information and systems. Computer literacy is the ability to use digital tools effectively. A computer scientist may analyse correctness or complexity; a computer-literate user may competently use an application without studying its algorithms or internal architecture.

  2. Distinguish computer science, information technology and software engineering, giving one example of each.
    Answer guidance

    Computer science focuses on computation and underlying principles; IT focuses on deploying and operating technology; software engineering focuses on disciplined development and maintenance of reliable software. Examples: analysing a search algorithm; administering a campus network; testing and maintaining a student portal.

  3. Explain decomposition, pattern recognition, abstraction and algorithm design using a university registration example.
    Answer guidance

    Decompose registration into identity verification, course selection, prerequisite checks and confirmation. Recognise repeated validation rules. Abstract a learner to the data needed for registration. Design a finite procedure that checks eligibility and records approved selections.

  4. Differentiate data, information and knowledge. Give a context-specific example.
    Answer guidance

    Data are raw observations; information is organised and contextualised data; knowledge is interpreted understanding used to make decisions. A reading of 38.5 is data; a labelled measurement with unit and time is information; an informed interpretation using other clinical evidence is knowledge.

  5. Explain six dimensions of data quality and give one example of a failure for any three.
    Answer guidance

    Accuracy, completeness, consistency, timeliness, validity and uniqueness. Examples: incorrect date (accuracy), missing currency (completeness), conflicting credit values (consistency), outdated timetable (timeliness), mark above 100 (validity), duplicate payment (uniqueness).

  6. Convert 45₁₀ to binary and verify your answer.
    Answer guidance

    45₁₀ = 101101₂. Verification: 32 + 8 + 4 + 1 = 45.

  7. Convert 110101₂ to decimal, showing the place-value expansion.
    Answer guidance

    (1×32)+(1×16)+(0×8)+(1×4)+(0×2)+(1×1)=53₁₀.

  8. Convert 11101111₂ to hexadecimal.
    Answer guidance

    Group as 1110 1111. 1110₂ = E and 1111₂ = F; therefore EF₁₆.

  9. Add 1011₂ and 0110₂. Verify the result in decimal.
    Answer guidance

    1011₂ + 0110₂ = 10001₂. Decimal check: 11 + 6 = 17, and 10001₂ = 17.

  10. An image is 1024 × 768 pixels at 24 bits per pixel. Calculate the uncompressed storage in bytes and state two reasons the actual file size may differ.
    Answer guidance

    1024×768×24÷8 = 2,359,296 bytes. Actual size may differ because of compression, headers, metadata, colour format or additional channels.

  11. Describe the functions of the control unit, ALU and registers in a CPU.
    Answer guidance

    The control unit coordinates instruction execution; the ALU performs arithmetic and logical operations; registers hold fast temporary values, addresses and control information.

  12. Explain the fetch–decode–execute cycle and use an example to show how an instruction changes a register.
    Answer guidance

    The processor fetches an instruction from memory, decodes its operation and operands, executes it, and writes back a result. For example, ADD R1,R2 adds R2 to R1 and stores the result according to the instruction set.

  13. Compare registers, cache, RAM and secondary storage in terms of speed, capacity and purpose.
    Answer guidance

    Registers are very small and fastest; cache is small and fast, reducing average memory access time; RAM holds active programs and data; secondary storage provides larger persistent capacity but is generally slower.

  14. A file of 80 MB is transferred at 16 Mb/s. Ignoring overhead, calculate the transfer time.
    Answer guidance

    80 MB × 8 = 640 Mb. Time = 640 ÷ 16 = 40 seconds.

  15. Explain four responsibilities of an operating system.
    Answer guidance

    Any four explained: process scheduling, memory management, file management, device/input-output management, user accounts and permissions, networking services, error handling and protection.

  16. Differentiate a program from a process.
    Answer guidance

    A program is a stored set of instructions; a process is an executing instance with state and allocated resources.

  17. Explain the role of IP, TCP or UDP, DNS and HTTPS in network communication.
    Answer guidance

    IP provides addressing and routing; TCP offers reliable ordered transport; UDP offers datagram transport without the same built-in reliability guarantees; DNS resolves domain names; HTTPS protects web communication using TLS.

  18. Discuss three ethical risks in a student attendance application that collects location data.
    Answer guidance

    Risks include excessive surveillance, unauthorised disclosure, inaccurate location-based penalties, unequal access for students without devices, insecure storage and unclear retention. Recommend data minimisation, access controls, transparency, correction and appeal mechanisms.

  19. Design a test plan for a program that accepts a mark from 0 to 100. Include normal, boundary and invalid cases.
    Answer guidance

    Examples: 56 (valid), 0 and 100 (valid boundaries), −1 and 101 (invalid), blank and alphabetic text (invalid input). State expected outcomes and record actual outcomes.

  20. Explain why processor clock speed alone is insufficient to compare two computers.
    Answer guidance

    Performance also depends on instructions per cycle, architecture, core count, cache, memory bandwidth and latency, storage, workload parallelism, thermal limits, software and energy constraints.
