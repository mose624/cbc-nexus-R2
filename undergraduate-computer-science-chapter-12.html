1. Web architecture and the internet

The web is a distributed information system built on internet protocols. A browser acts as a client that requests resources from servers using application protocols such as HTTP. DNS resolves domain names; IP routes packets; transport protocols carry data; TLS protects supported connections. A web application may include a browser interface, application server, database, object storage, cache and external services. Architecture should define trust boundaries, data ownership, failure handling and responsibilities for each component.

2. HTML semantics and document structure

HTML describes the structure and meaning of web content. Semantic elements such as header, nav, main, article, section, aside and footer communicate document roles. Headings should form a logical hierarchy; forms need associated labels; images require meaningful alternative text when they convey information. Valid structure improves accessibility, maintainability and machine interpretation. Use elements according to their meaning rather than choosing tags solely for their default visual appearance.

3. CSS layout, responsive design and visual systems

CSS controls presentation, typography, colour, spacing and layout. The cascade, inheritance and specificity determine which declarations apply. Flexbox is useful for one-dimensional alignment; Grid supports two-dimensional layouts; normal flow remains important for robust documents. Responsive design adapts content to viewport and user settings using flexible units, fluid images and media queries. Design systems define reusable tokens and components, improving consistency while preserving readable contrast and keyboard focus.

4. JavaScript and browser programming

JavaScript adds behaviour to web pages and can run in browsers and server environments. Variables, functions, objects, arrays, modules, promises and asynchronous operations are core concepts. The Document Object Model represents a page as a tree that scripts can inspect and update. Event handlers respond to user actions. Avoid blocking the main thread with expensive work, handle rejected promises and validate assumptions about network responses. Separate data logic from presentation to improve testing.

5. HTTP, URLs, cookies and web communication

HTTP uses requests and responses. Methods such as GET, POST, PUT, PATCH and DELETE express intended operations, while status codes communicate outcomes. URLs identify resources; headers carry metadata; bodies contain representations or submitted data. Cookies can maintain sessions but require appropriate security attributes such as Secure, HttpOnly and SameSite. Caching improves performance when freshness and privacy are handled correctly. Understand idempotency and safe methods when designing APIs and retry behaviour.

6. Client-server applications and backend development

A backend receives requests, applies business rules, authenticates and authorises users, accesses data stores and returns responses. Clear separation between routing, validation, domain logic and persistence supports maintainability. Server-side validation is essential even when client-side validation improves usability. Use structured error handling, configuration management, rate limits and observability. Avoid exposing stack traces, secrets or internal implementation details to clients.

7. APIs, REST principles and data formats

An application programming interface defines how software components communicate. REST-style APIs model resources and use HTTP semantics; JSON is a common representation, though other formats exist. Good API design uses predictable paths, appropriate methods and status codes, validation, pagination, versioning and documented error formats. Authentication does not replace authorisation: each request must check whether the caller may access the requested resource. Protect APIs against abuse through quotas and monitoring.

8. Databases, state and web application data

Web applications commonly persist structured data in relational databases or use document, key-value, graph and other data stores. Choose a data model based on relationships, query patterns, consistency requirements and operational needs. Use parameterised queries, transactions and constraints. Sessions, caches and client-side state have different lifetimes and trust levels. Never treat browser storage as a secure place for secrets. Plan migrations, backups, retention and data deletion.

9. Accessibility, usability and inclusive interaction

Accessible applications support users with different sensory, motor, cognitive and language needs. Use semantic HTML, keyboard operability, visible focus, adequate contrast, captions, labels and helpful error messages. Do not communicate meaning by colour alone. Test with keyboard navigation, zoom, screen readers and automated tools, while recognising that automated checks cannot assess every user experience. Usability testing with representative participants reveals barriers that developers may not anticipate.

10. Web application security and privacy

Common web risks include injection, cross-site scripting, cross-site request forgery, broken access control, insecure authentication, unsafe file uploads and security misconfiguration. Encode untrusted output for its context, use CSRF protections where applicable, enforce server-side access checks, store passwords using modern password-hashing algorithms and protect transport with TLS. Apply content security policy carefully, manage dependencies and minimise personal data. Security headers and scanning complement—not replace—secure implementation.

11. Testing, deployment, performance and maintenance

Test web systems at unit, integration, end-to-end, accessibility, security and performance levels. Use representative environments and synthetic data where possible. Deployment may use immutable builds, staged releases, automated checks and rollback plans. Performance work includes image optimisation, compression, caching, efficient queries and reduced JavaScript payloads. Monitor availability, errors, latency and user-facing outcomes. Maintain documentation, dependency updates, backups and incident response procedures after launch.

Examination and revision questions

Answer using precise definitions, diagrams, calculations and examples where appropriate.

  1. What is the role of HTML?

    Show answer guidance

    HTML defines the structure and semantics of web content.

  2. What is CSS used for?

    Show answer guidance

    CSS controls presentation, layout, typography and responsive styling.

  3. What is the DOM?

    Show answer guidance

    A structured object representation of a document that scripts can inspect and modify.

  4. Differentiate GET and POST.

    Show answer guidance

    GET requests a representation and is intended to be safe; POST submits data for processing or resource creation.

  5. What does DNS do?

    Show answer guidance

    It resolves domain names into records such as IP addresses.

  6. What is a REST-style API?

    Show answer guidance

    An interface that models resources and uses HTTP methods and representations to interact with them.

  7. Why validate input on the server?

    Show answer guidance

    Client-side checks can be bypassed; the server is the trusted enforcement point for data rules.

  8. What is responsive design?

    Show answer guidance

    Designing interfaces that adapt to different viewports, devices and user settings.

  9. Name two accessibility practices.

    Show answer guidance

    Use semantic elements, keyboard support, visible focus, labels, contrast and meaningful alternative text.

  10. What is cross-site scripting?

    Show answer guidance

    A vulnerability where untrusted content is executed as script in another user's browser.

  11. Why use parameterised SQL queries?

    Show answer guidance

    They separate query structure from data values and reduce injection risk.

  12. What is a cookie used for?

    Show answer guidance

    It stores small browser-managed values, often for session or preference state.

  13. Name three HTTP status code classes.

    Show answer guidance

    2xx success, 3xx redirection, 4xx client errors and 5xx server errors.

  14. What is continuous deployment?

    Show answer guidance

    An automated process that releases validated changes to production, subject to configured safeguards.

  15. Why monitor a deployed web application?

    Show answer guidance

    To detect errors, latency, availability problems, security events and changing user needs.
