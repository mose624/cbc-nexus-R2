1. Database concepts and database management systems

A database is an organised collection of related data maintained to support defined operations and users. A database management system (DBMS) provides facilities to define structures, store and retrieve data, enforce constraints, manage concurrent access, control permissions and recover from failures. A database system includes the database, DBMS software, applications, people, procedures and computing infrastructure. The DBMS separates logical data organisation from many physical storage details, reducing application dependence on file layouts.

2. Database architectures and data independence

A DBMS may use a centralised, client-server, distributed or cloud-hosted architecture. In a three-schema view, the external level represents user-specific views, the conceptual level describes the overall logical structure, and the internal level describes physical storage. Logical data independence means changing the conceptual schema need not require changes to every external view. Physical data independence means storage changes can be made without changing the logical schema. These abstractions support maintainability and controlled evolution.

3. Requirements analysis and entity-relationship modelling

Database design begins by identifying stakeholders, data requirements, business rules, transactions, privacy needs and expected workload. Entity-relationship (ER) models describe entity types, attributes and relationships. An entity represents a distinguishable object or concept; an attribute records a property; a relationship connects entities. Cardinality describes how many instances may participate, such as one-to-one, one-to-many or many-to-many. Optionality indicates whether participation is mandatory. Resolve ambiguous rules with users before implementing tables.

4. Relational model, keys and integrity constraints

The relational model represents data as relations, commonly implemented as tables. Rows represent tuples and columns represent attributes. A candidate key uniquely identifies a row; a primary key is the selected candidate key. A foreign key references a candidate or primary key in another relation. Entity integrity requires primary key values to be unique and non-null. Referential integrity requires foreign-key values to match referenced values or follow an explicitly permitted null rule. Domain constraints restrict valid attribute values.

5. Relational algebra and relational operations

Relational algebra provides formal operations for manipulating relations. Selection filters rows, projection chooses columns, union combines compatible relations, difference finds rows in one relation but not another, and Cartesian product pairs rows. Joins combine related tuples using matching conditions. These operations provide a theoretical basis for SQL query processing. Understanding them helps students reason about query meaning, identify unnecessary intermediate results and recognise how query optimisers may reorder equivalent operations.

6. SQL: data definition and manipulation

Structured Query Language (SQL) is used to define, query and manipulate relational data. DDL statements such as CREATE and ALTER define schema objects. DML statements such as INSERT, UPDATE and DELETE modify rows. SELECT retrieves data using projections, filters, joins, grouping, aggregation and ordering. Constraints should be declared in the database where appropriate, not only in application code. Use parameterised queries for user-supplied values to reduce SQL injection risk.

7. Normalization and relational design

Normalization organises relations to reduce redundancy and undesirable update anomalies. First normal form requires atomic attribute values under the chosen model. Second normal form removes partial dependency of non-key attributes on a proper subset of a candidate key. Third normal form removes relevant transitive dependencies; Boyce-Codd normal form strengthens determinant requirements. Normalization is guided by functional dependencies and candidate keys. Denormalization may sometimes improve read performance, but should be measured and documented.

8. Transactions and ACID properties

A transaction is a logical unit of database work. Atomicity means all operations in the transaction succeed or the transaction is rolled back. Consistency means constraints remain satisfied. Isolation controls the visibility of concurrent work. Durability means committed changes survive failures within the guarantees of the system. Transactions are essential for tasks such as transferring funds, registering students or updating inventory, where partial completion could leave data inconsistent.

9. Concurrency control and recovery

Concurrent transactions can cause lost updates, dirty reads, non-repeatable reads and phantom rows depending on isolation guarantees. Locking, multiversion concurrency control and serialisation techniques help preserve correctness. Deadlocks can occur when transactions wait cyclically for resources; systems detect or prevent them using strategies such as timeout or victim rollback. Recovery uses logs, checkpoints and backups to restore a consistent state after crashes or operational mistakes.

10. Indexes, query processing and optimisation

An index is an auxiliary structure that speeds up retrieval by helping locate rows without scanning an entire table. B-tree indexes support ordered lookup and range queries; hash indexes suit equality lookup in supported systems. Indexes consume storage and add work to inserts, updates and deletes. A query optimiser estimates costs and selects an execution plan using available statistics, indexes and join strategies. Examine query plans and measure realistic workloads before adding indexes.

11. Database security, administration and distributed data

Database security includes authentication, least-privilege authorisation, role-based access, encryption, auditing, secure configuration and patch management. Backups should be protected, tested and retained according to recovery objectives. Replication maintains copies for availability or read scaling; sharding partitions data across nodes. Distributed systems must consider network failure, replication lag, consistency and transaction coordination. Compliance duties vary by jurisdiction and data type, so minimise collection and define retention and access policies.

Examination and revision questions

Answer each question with precise definitions, diagrams, calculations or technical examples where appropriate.

  1. What is a DBMS?

    Show answer guidance

    Software that defines, stores, retrieves, updates and controls access to databases while supporting integrity, concurrency and recovery.

  2. Differentiate a database and a DBMS.

    Show answer guidance

    A database is the organised data; a DBMS is the software that manages it.

  3. What is an ER model?

    Show answer guidance

    A conceptual model describing entity types, attributes and relationships.

  4. Define a primary key.

    Show answer guidance

    A selected candidate key that uniquely identifies each row in a relation.

  5. What is a foreign key?

    Show answer guidance

    An attribute or set of attributes referencing a candidate key in another or the same relation.

  6. What is referential integrity?

    Show answer guidance

    The rule that foreign-key references must be valid according to the database constraint.

  7. What does SQL SELECT do?

    Show answer guidance

    Retrieves rows and expressions from one or more data sources.

  8. What is normalization?

    Show answer guidance

    Organising relations using dependencies to reduce redundancy and update anomalies.

  9. State the ACID properties.

    Show answer guidance

    Atomicity, consistency, isolation and durability.

  10. What is a dirty read?

    Show answer guidance

    Reading data written by a transaction that has not yet committed.

  11. Why are indexes used?

    Show answer guidance

    To accelerate data retrieval by providing an auxiliary access path.

  12. What is a query execution plan?

    Show answer guidance

    The operations and access strategies chosen to execute a database query.

  13. What is SQL injection?

    Show answer guidance

    An attack in which untrusted input changes the meaning of a database query.

  14. Why test database backups?

    Show answer guidance

    To verify that data can actually be restored within required recovery objectives.

  15. What is database replication?

    Show answer guidance

    Maintaining copies of data on multiple database instances or nodes.
